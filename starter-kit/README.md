# Starter Kit

The A-Dev starter kit is the shortest path from doctrine to repeatable practice across repos, teams, and industries.

This is the implementation kit for the [A-Dev practice](../framework/README.md). For agent capability design, also use the [Hardness skill contract](../framework/hardness/02-skill-contract-template.md) and the [Trust Ladder & Autonomy Levels](../framework/hardness/08-trust-ladder-and-autonomy-levels.md).

## Adoption path
- `DAY_0.md`: establish the minimum operating skeleton.
- `FIRST_WEEK.md`: run the first evidence-backed iteration cycle.
- `FIRST_RELEASE.md`: close the first release with traceability and verification.
- `OPERATING_RITUALS.md`: compact rituals derived from Homedir execution history.
- `examples/minimal-adev-loop/`: a minimal, repo-agnostic sample to model the workflow.

## Existing assets
- `.ai-sdlc.yaml`: canonical per-repository autonomy and trust ladder configuration.
- `ai-sdlc_template.yaml`: declarative AI-SDLC configuration contract for autonomous agents, CI gates, review policy, and Progressive Autonomy Ladder.
- `BASELINE_template.json`: machine-readable baseline seed.
- `.ai-sdlc.yaml`: repository AI SDLC policy template inheriting organizational baseline rulesets and non-overridable security floors.
- `DECISION_LOG.md`: capture decisions and reversals.
- `AGENT_ISSUE_template.md`: copyable issue template conforming to the [Hardness Definition-of-Ready](../framework/hardness/08-issue-definition-of-ready.md).
- `QUALITY_CYCLE_checklist.md`: broad quality cycle checklist.

## Use rule
Do not treat these files as theory-only templates. Copy, adapt, and keep them aligned with the actual repository you are operating.
